# AI Usage Report

**Assignment:** Assignment 5 — Admission Lead Management

---

## AI Tool Used
**Kiro (AI-powered IDE by AWS)** — an agentic AI development environment built on VS Code that can read, write, and run code autonomously.

---

## My Role vs AI's Role

I made all the product and flow decisions: what the system should do, how leads move through the pipeline, what counts as an edge case, what thresholds make sense, and what the UI should communicate. AI wrote the code based on those decisions. I reviewed, tested, and corrected the output.

---

## What I Asked AI To Do

1. **Generate the backend** — I specified the data model (leads with phone as unique key, counsellor assignment, notes log, source tracking), the API routes, the duplicate detection logic (409 with existing lead ID), the ageing threshold (7 days), and the follow-up urgency rule (2 days no contact, or 3 days since last follow-up). AI wrote the Express server to those specs.

2. **Generate the React frontend** — I specified three pages: Dashboard (pipeline counts, conversion funnel with drop-off %, source bar chart, counsellor performance table, alert banners), Leads list (filterable by status/source/counsellor/search, add lead modal with validation, CSV export), and Lead Detail (full edit for all fields including name/phone/email, status stepper, follow-up notes log, quick action buttons). AI built these to my spec.

3. **Generate the CSS design system** — I specified the visual approach: no external UI libraries, custom CSS only, color-coded status and source badges, frosted glass sidebar drawer, toast notifications for every user action, smooth animations. AI implemented it.

4. **Add the sliding sidebar and navigation** — I designed the navigation flow: sidebar as an overlay drawer with a fixed hamburger icon, auto-close after 5 seconds, a global topbar showing brand name and current page, and funnel rows on the dashboard that navigate to filtered lead lists. AI wired it up.

5. **Add the duplicate warning UI** — I decided that a 409 response should not just show a generic error — it should show a specific message with a direct "View existing lead →" button. AI implemented the UI, but missed wiring the `onViewDuplicate` prop to the modal render call. I identified and fixed the bug.

6. **Set up Docker** — I asked AI to containerise the backend and frontend for one-command deployment. AI generated the Dockerfiles, nginx config, and docker-compose.

## Code I Modified / Reviewed

- **Fixed a bug in the duplicate warning** — AI coded the `onViewDuplicate` handler inside `AddLeadModal` correctly but never passed the prop when rendering the modal in `Leads.js`. The button existed but did nothing. I identified this by clicking the button during testing and saw nothing happen. Fixed by passing `onViewDuplicate={id => { setShowModal(false); onViewLead(id); }}` to the modal.
- **Reviewed ageing and follow-up thresholds** — confirmed 7-day and 3-day values made sense for a real admissions cycle and verified the seed data dates made these flags visible on first load.
- **Reviewed duplicate detection** — confirmed it keyed on phone number, not email. Email is optional in this domain; phone is always collected and is the right unique key.
- **Reviewed the conversion funnel drop-off formula** — verified `(prev - current) / prev * 100` was correct per stage.
- **Adjusted the sidebar auto-close timer** from 3s to 5s — 3 seconds was too fast during testing, users did not have enough time to select a page.
- **Adjusted CSS easing** on the sidebar slide to `cubic-bezier(0.4, 0, 0.2, 1)` for a smoother feel.

---

## AI Output That Was Wrong

1. **Duplicate warning prop not wired** — AI wrote the component correctly but forgot to pass `onViewDuplicate` at the call site. Button appeared but did nothing. Fixed by adding the missing prop.

2. **Hamburger button position** — AI used `position: absolute` which caused it to scroll with the page content. Identified visually. Fixed by switching to `position: fixed` with explicit coordinates.

3. **ESLint rule reference** — AI used `// eslint-disable-next-line react-hooks/exhaustive-deps` but the project did not have that plugin configured, causing a compile error. Identified from the browser error overlay. Fixed by using the generic `// eslint-disable-line` instead.

4. **Sidebar overlapping logo text** — Initial sidebar pushed the layout and the brand text was clipped. Identified visually. Fixed by converting to a floating overlay drawer using `translateX` animation.

---

## How I Identified the Problems

- Duplicate warning: clicked the button during browser testing, nothing happened, read the component and traced the missing prop
- Hamburger position: visual testing showed it scrolling with page content instead of staying fixed
- ESLint error: browser error overlay showed the exact file, line, and rule name
- Sidebar overlap: visual inspection showed the logo text being cut off

---

## How I Fixed Them

- Duplicate warning → added `onViewDuplicate` prop at the modal render site in `Leads.js`
- Hamburger → changed to `position: fixed` with explicit `top` / `left` values
- ESLint → replaced specific rule comment with generic `// eslint-disable-line`
- Sidebar → redesigned to floating overlay with slide-in animation
